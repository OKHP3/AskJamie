## PHASE 3 — JAVASCRIPT AUDIT (PRIORITY: HIGH)

Read `assets/js/app.js` completely. Audit for:

**3.1 — Mobile navigation toggle**
The `nav-toggle` button must correctly toggle the mobile nav open/closed. Verify:

- The button toggles `aria-expanded` between `"true"` and `"false"`
- The nav visually shows/hides on toggle
- The menu closes when a nav link is clicked (especially important for same-page anchor links)
- The menu closes when the user clicks/taps outside the nav
- Keyboard accessibility: pressing Escape closes the menu

If any of these behaviors are missing or broken, fix them.

**3.2 — Scroll reveal animations**
The `.reveal-on-scroll` class is applied to multiple sections. Verify an IntersectionObserver (or equivalent) is correctly initializing these reveals. Common bugs: observer not initialized on DOMContentLoaded, elements never getting their “visible” class added, or the CSS transition not being defined. Fix any gaps.

**3.3 — Dynamic copyright year**
The `#current-year-askjamie` span should be populated with the current year via JavaScript. Verify this is working and that it does NOT hard-code a year. If the script is missing or broken, add: `document.getElementById('current-year-askjamie').textContent = new Date().getFullYear();`

**3.4 — `mermaid-init.js`**
Read this file. If it’s attempting to initialize Mermaid diagrams but no `.mermaid` blocks exist on any current page, the import is loading unnecessarily. Either: (a) defer it to only load on pages that actually have diagrams, or (b) confirm it’s lightweight enough to be harmless and document why it’s included globally. Do not leave unexplained module-type scripts loading on pages where they have no effect.

**3.5 — `analytics.js`**
Read this file. Verify it correctly initializes Google Analytics with tag `G-MT9Y10YY0G`. Verify it does NOT duplicate the GA initialization already done via `gtag.js` inline script in `index.html`. Remove any double-initialization. Confirm the script is `defer`red, not `async`, so it does not block rendering.

**3.6 — Ko-fi overlay widget**
`https://storage.ko-fi.com/cdn/scripts/overlay-widget.js` is loaded at the end of `index.html`. Verify: (a) this script is actually initializing a Ko-fi widget somewhere, and (b) there’s a corresponding configuration call (Ko-fi requires `kofiWidgetOverlay.draw(...)` to be called). If the initialization call is missing, either add it correctly or remove the unused script tag.

**3.7 — Error handling**
Check all JavaScript for unhandled promise rejections, undefined variable references, or querySelector calls that may return null. Add null guards where appropriate.

## PHASE 4 — CSS / VISUAL DESIGN AUDIT (PRIORITY: HIGH)

Read `assets/css/theme.css` completely. Audit for:

**4.1 — CSS custom properties (variables) consistency**
Verify a complete and consistent design token set is defined in `:root`. Minimum expected tokens:

- `--color-primary` (teal/blue-teal family)
- `--color-secondary`
- `--color-bg` (cream/paper-grain background)
- `--color-text`
- `--color-accent`
- `--font-heading` (Baloo 2)
- `--font-body` (Open Sans)
- `--font-handwritten` (Kalam, for accent elements)
- Border radius, spacing scale, shadow definitions

If these are not defined as variables but instead as hard-coded hex values scattered throughout the file, refactor them into variables. This makes future brand updates a single-line change instead of a global find-replace.

**4.2 — Mobile responsiveness**
Audit all breakpoints. The site must be fully functional and visually correct at:

- 320px (small phone)
- 375px (iPhone SE / standard phone)
- 768px (tablet)
- 1024px (small desktop)
- 1440px (standard desktop)

Check specifically:

- Navigation: does the mobile hamburger menu appear correctly below 768px?
- Hero section: does the two-column grid collapse to single-column on mobile?
- Card grids: do `.grid-3` layouts collapse properly?
- Images: are they ever overflowing their containers?
- Footer: does the three-column footer stack gracefully on mobile?
- Typography: are font sizes readable on small screens (body min 16px)?

Fix any layout breaks found.

**4.3 — Dark mode support**
The index.html sets `data-theme="light"` on the `<body>` and `<meta name="color-scheme" content="light dark">`. Verify:

- Is there a `[data-theme="dark"]` CSS block defined?
- Is there a toggle mechanism for the user to switch themes, OR is it purely OS-preference driven via `prefers-color-scheme`?
- If dark mode CSS exists, verify it applies correct colors to all major UI components (nav, hero, cards, footer, buttons)
- If dark mode CSS does NOT exist at all, either remove the `color-scheme` meta claim or implement a basic dark mode that at minimum doesn’t break the site for users with OS dark mode set

**4.4 — Button states**
Verify all `.btn` elements have defined `:hover`, `:focus`, and `:active` states. Focus states must be visible (do not simply set `outline: none` without a replacement focus indicator — this is an accessibility violation).

**4.5 — Typography hierarchy**
Verify that h1, h2, h3, h4, p, and caption elements have visually distinct, consistent styling. No two heading levels should look the same.

**4.6 — Unused CSS**
Identify any CSS class definitions in theme.css that are not referenced anywhere in any HTML file. Flag them. If they are clearly dead code and not part of a planned feature, remove them.

**4.7 — Print stylesheet**
The Google Fonts are loaded with `media="print"` then switched to `media="all"` via `onload`. Verify this pattern is working correctly and not causing a flash of unstyled text on initial load. If it is causing FOUT issues, consider using `font-display: swap` in the font URL parameters instead.

## PHASE 5 — SEO & METADATA AUDIT (PRIORITY: MEDIUM-HIGH)

**5.1 — Per-page title and description uniqueness**
Every HTML page must have a unique `<title>` tag and a unique `<meta name="description">`. Audit every page. If any two pages share an identical title or description, that is an SEO error. Fix by writing page-specific titles and descriptions.

Title format to enforce: `[Page-Specific Title] | AskJamie™`
Example: `Lens System — Interpretive AI Frameworks | AskJamie™`

**5.2 — Open Graph completeness**
Every page must have a full OG tag set:

- `og:title` (page-specific)
- `og:description` (page-specific, not copy-pasted from index)
- `og:type` (`website` for most, `article` for case studies)
- `og:url` (canonical URL for this specific page)
- `og:image` (the right image for this page, not always the generic avatar)
- `og:image:width` and `og:image:height`
- `og:site_name`
- `og:locale`

Audit every page. Add any missing OG tags.

**5.3 — Twitter/X Card completeness**
Same as OG — every page should have page-specific Twitter card tags. Audit and fix.

**5.4 — Canonical links**
Every page must have a `<link rel="canonical" href="[full-URL-of-this-page]">`. Audit all pages. Add any missing canonicals. Verify the canonical URLs use `https://`, not `http://`, and use trailing slashes consistently (pick one convention and stick to it).

**5.5 — Sitemap accuracy**
Read `sitemap.xml`. Verify it includes every publicly accessible page on the site. Add any pages that are missing. Remove any pages that are referenced in the sitemap but do not actually exist. Update `<lastmod>` dates where appropriate.

**5.6 — Robots.txt**
Read `robots.txt`. Verify it correctly allows search engines and does not accidentally block any publicly-intended content. Verify the `Sitemap:` directive points to `https://askjamie.bot/sitemap.xml`.

**5.7 — llms.txt**
Read `llms.txt`. This file controls how AI crawlers (like those powering AI search) interpret the site. Verify it accurately describes AskJamie™, its purpose, its content, and its canonical links. Update it if the content description is outdated or incomplete.

**5.8 — JSON-LD structured data**
`index.html` contains two JSON-LD blocks (WebSite and Organization). Audit both:

- Remove the `SearchAction` from the WebSite schema if no site search functionality exists
- Verify the Organization schema `sameAs` array accurately reflects all official AskJamie™ / OKHP³™ social and brand presences (LinkedIn, Ko-fi, Facebook, X/Twitter, YouTube, overkillhill.com, glee-fully.tools)
- Consider adding a `Person` schema for Jamie as the human behind the brand, if appropriate

**5.9 — Image alt text**
Every `<img>` on every page must have a descriptive `alt` attribute. Decorative images should have `alt=""` (empty string). Functional images (like logo, avatar, case study illustrations) must have meaningful alt text. Audit all pages and fix any missing or generic alt attributes.

## PHASE 6 — ACCESSIBILITY AUDIT (PRIORITY: HIGH)

Run a complete accessibility audit against WCAG 2.1 AA standards.

**6.1 — Color contrast**
Verify all text/background color combinations meet WCAG AA minimum contrast ratios:

- Normal text: 4.5:1 minimum
- Large text (18pt+ or 14pt+ bold): 3:1 minimum
- UI components and focus indicators: 3:1 minimum

If the muted teal palette is causing contrast failures on cream backgrounds, adjust the specific shade until contrast requirements are met without destroying the visual identity.

**6.2 — Heading hierarchy**
Every page must have exactly one `<h1>`. Sub-headings must follow logical order (h2 → h3 → h4, not jumping levels). Audit all pages.

**6.3 — Focus management**

- All interactive elements (links, buttons, form fields) must be keyboard-focusable in logical order
- The “Skip to content” link must be the first focusable element in the DOM and must become visible on focus
- The mobile nav toggle must be keyboard operable
- No focus traps outside of modal dialogs (and there should be no modals on this site currently)

**6.4 — ARIA labels**

- The primary nav must have `aria-label="Primary navigation"` or equivalent
- Icon-only links (social links in the footer with text labels are fine, but check for any that are icon-only) must have `aria-label` attributes
- The mobile hamburger button must have `aria-expanded` correctly toggled and `aria-controls` pointing to the nav element’s ID
- Section elements without visible headings must have `aria-labelledby` or `aria-label`

**6.5 — Form accessibility** (contact page specifically)
If a form exists:

- Every input must have an associated `<label>` (not placeholder text as a substitute for labels)
- Required fields must be indicated via `aria-required="true"` and a visual indicator
- Error states must be communicated via `aria-describedby` pointing to error messages

**6.6 — Language attribute**
Every page’s `<html>` tag must have `lang="en"`. Verify this is present on all pages.

**6.7 — Link text**
No link should have text-only content of “click here,” “here,” “more,” or “read more” without surrounding context. All links must make sense out of context (they will be read by screen readers in list mode). Fix any non-descriptive link text.

## PHASE 7 — PERFORMANCE AUDIT (PRIORITY: MEDIUM)

**7.1 — Image optimization**
The site serves multiple 1024x1024 PNG images. These are massive for web use. For each image:

- Verify the image is being served at a size appropriate to its actual display size (a 40x40px avatar in the nav does not need a 1024x1024 source)
- Add `width` and `height` attributes to all `<img>` tags if missing (prevents layout shift)
- Verify all non-hero images use `loading="lazy"`
- Verify hero/above-fold images use `loading="eager"` or no loading attribute (default)
- Add `decoding="async"` to all images that don’t already have it
- Consider adding `<link rel="preload">` for the hero image specifically

Note: Do not convert or recompress image files as this may exceed scope; instead flag the specific images that should be optimized and document the recommended target dimensions for each use case.

**7.2 — Script loading order**
Audit all `<script>` tags across all pages. Verify:

- Render-blocking scripts (no `async` or `defer`) only appear if absolutely necessary
- `analytics.js` is `defer`red (not `async`) so it doesn’t delay interactive content
- Third-party scripts (Ko-fi, Google Tag Manager) are loaded last and do not block page paint
- The `type="module"` script for mermaid-init is only loaded on pages where it’s needed

**7.3 — Font loading strategy**
The current approach loads fonts with `media="print"` then switches to `media="all"` via `onload`. This is a valid FOIT-avoidance technique, but it requires the `<noscript>` fallback to be present (it is). Verify this is consistent across all pages, not just index.html.

**7.4 — Redundant resource loading**
Check if `theme.css` or `app.js` are being loaded more than once on any page. Check for duplicate Google Fonts calls.
