## STEP 13.2 — AUDIT EXISTING TEMPLATES

Check whether `/assets/templates/` currently exists. If it does not exist, create the directory.

Scan `/assets/templates/` for any existing `.html` files. For each file found, determine which Page Type it covers by reading its structure. Update the inventory table’s “Template Exists?” column for each match found. A template counts as existing only if it:

- Is an `.html` file (not a `.md` or `.txt` description)
- Contains the full `<head>` block with proper metadata placeholders
- Contains the site header with navigation
- Contains the site footer
- Has been stripped of page-specific body content (replaced with structured placeholders, not just blank space)

If a file in `/assets/templates/` does not meet all four criteria, it does not count as a valid template — note it as “EXISTS BUT INVALID” and include it in the generation queue for replacement.

## STEP 13.3 — GENERATE MISSING TEMPLATES

For every Page Type that does not have a valid template, generate one now.

### Template Generation Rules

**Rule 1 — Source of truth**
Base each template on the actual production page of that type. Do not invent structure from scratch. Read the real page, strip its specific content, and save the result as the template. The template must accurately reflect what the production page actually looks like structurally, not what you think it should look like.

**Rule 2 — What to strip**
Remove all of the following from the page copy when creating the template:

- All specific body text (headlines, paragraphs, list items, card content)
- All specific image `src` paths (replace with placeholder values — see Rule 5)
- All specific link `href` values that point to content-specific targets (keep structural nav hrefs intact)
- All page-specific JSON-LD structured data content (keep the schema type stub, clear the values)
- All specific page titles and meta descriptions (replace with placeholder tokens — see Rule 4)

**Rule 3 — What to preserve**
Keep all of the following intact:

- Complete `<head>` metadata block structure (all meta tag names and attributes, just with placeholder values)
- All CSS class names, exactly as they appear in the source
- All structural HTML elements and their nesting (`<section>`, `<article>`, `<div class="container">`, `<header>`, `<footer>`, `<nav>`, etc.)
- The site navigation with all links intact (nav is not page-specific)
- The site footer with all links intact
- The “Today’s Special” banner markup (with its link cleared to `#` and text replaced with a placeholder)
- All `aria-` attributes (filled with placeholder values where they referenced specific text)
- All `id` attributes (these define page structure and must be preserved)
- All `data-` attributes
- All `<script>` tags at the bottom of `<body>` (they’re structural, not content)
- All `<link>` tags in `<head>`

**Rule 4 — Placeholder token format**
Use double-bracket tokens for all replaceable content. Examples:

```
[[PAGE-TITLE]]
[[PAGE-DESCRIPTION]]
[[PAGE-URL]]
[[OG-IMAGE-URL]]
[[SECTION-HEADING]]
[[BODY-COPY]]
[[CTA-LABEL]]
[[CTA-URL]]
[[CARD-TITLE]]
[[CARD-BODY]]
[[IMAGE-SRC]]
[[IMAGE-ALT]]
[[ARTICLE-TITLE]]
[[ARTICLE-BODY]]
[[LENS-NUMBER]]
[[LENS-NAME]]
[[LENS-TAGLINE]]
[[CASE-STUDY-BRAND]]
[[GPT-URL]]
[[STRUCTURED-DATA-VALUE]]
```

Use the most specific token name that describes the content’s purpose. Do not use generic tokens like `[[CONTENT]]` for everything — a card title and a hero headline should have different token names.

**Rule 5 — Image placeholders**
Replace all specific image `src` values with the token `[[IMAGE-SRC]]` and all `alt` values with `[[IMAGE-ALT]]`. Keep `width` and `height` attributes intact so layout doesn’t break during template use. Example:

```html
<!-- BEFORE (production) -->
<img src="assets/img/AskJamie AvatarTallLeft Square 1024.png" alt="AskJamie™ avatar" width="40" height="40">

<!-- AFTER (template) -->
<img src="[[IMAGE-SRC]]" alt="[[IMAGE-ALT]]" width="40" height="40">
```

**Exception**: The nav logo and footer logo image paths may be left as their real values since they are shared infrastructure, not page-specific content.

**Rule 6 — Comment every placeholder block**
Above each section that contains placeholder tokens, add an HTML comment explaining what the section is for. Example:

```html
<!-- ================================================
  TEMPLATE SECTION: Hero
  Purpose: Primary above-the-fold intro for this page type.
  Required fields: [[PAGE-TITLE]], [[HERO-SUBTITLE]], [[HERO-TAGLINE]], [[CTA-LABEL]], [[CTA-URL]], [[IMAGE-SRC]], [[IMAGE-ALT]]
  Optional fields: [[SITE-STATUS-MESSAGE]] (only if page is in early-access state)
================================================ -->
```

**Rule 7 — Template header block**
At the very top of each template file, before `<!DOCTYPE html>`, add an HTML comment block:

```html
<!--
  ============================================================
  ASKJAMIE™ PAGE TEMPLATE
  ============================================================
  Template Type  : [[PAGE-TYPE-LABEL]]
  Source Page    : [[SOURCE-PAGE-PATH]]
  Template Path  : /assets/templates/[[TEMPLATE-FILENAME]]
  Generated      : [[GENERATION-DATE]]
  Generator      : Replit Agent — AskJamie Full-Site Audit
  ============================================================
  USAGE INSTRUCTIONS:
  1. Copy this file to the appropriate directory and rename it index.html
  2. Search for all [[ ]] tokens and replace with real content
  3. Update the <link rel="canonical"> to the new page's URL
  4. Update all Open Graph og:url and og:title meta tags
  5. Update the JSON-LD structured data values
  6. Add page-specific JavaScript if needed (do not remove existing script tags)
  7. Remove this comment block before publishing
  ============================================================
-->
```

Replace all `[[...]]` tokens in the header block with their real values at generation time.

## STEP 13.4 — TEMPLATE FILENAME CONVENTION

Save all generated templates using this filename pattern:

```
/assets/templates/template--[page-type-label].html
```

Examples:

```
/assets/templates/template--homepage.html
/assets/templates/template--interior-single.html
/assets/templates/template--interior-form.html
/assets/templates/template--hub.html
/assets/templates/template--lens-detail.html
/assets/templates/template--case-study.html
/assets/templates/template--error.html
/assets/templates/template--holding.html
/assets/templates/template--utility.html
```

If multiple source pages share the same Page Type label (e.g., Lens 01, 02, and 03 are all `lens-detail`), generate only **one** template for that type, based on the most complete/representative source page among them. Do not create separate `template--lens-detail-01.html`, `template--lens-detail-02.html`, etc. — one template per structural type is the rule.

```markdown
## How to Use a Template

1. Copy the desired template file to the target directory and rename it `index.html`.
2. Open the file and use Find & Replace to locate all `[[` tokens.
3. Replace each token with real content appropriate to the page.
4. Update the `<link rel="canonical">` href.
5. Update `og:url`, `og:title`, `og:description`, `og:image` meta tags.
6. Update the JSON-LD structured data block with real values.
7. Remove the template header comment block at the top of the file.
8. Add any page-specific CSS classes or JS as needed without modifying shared files.
9. Test on mobile and desktop before committing.

---

## Adding a New Template

If a new page type is introduced that doesn't match any existing template:
1. Build the page using the closest existing template as a starting point.
2. Once the page is production-ready, create a stripped template from it using the rules in Phase 13.
3. Add the new template to this index.
4. Commit both the new page and new template together.
```
